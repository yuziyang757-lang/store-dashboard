# AI 门店增长顾问 — 经营看板

一个面向实体门店老板的 **AI 经营日报系统**。管理员录入数据，系统自动生成经营分析、行动建议，老板通过只读看板查看。

> **核心理念：** 先用手工+工具验证需求，再逐步自动化。  
> 参考：[Wizard of Oz MVP](https://zh.wikipedia.org/wiki/%E7%B6%A0%E9%87%8E%E4%BB%99%E7%B8%AB%E5%9E%8B%E6%9C%80%E5%B0%8F%E5%8F%AF%E8%A1%8C%E7%94%A2%E5%93%81)

## 功能总览

### 管理员端 (`index.html`)

| 功能 | 说明 |
|------|------|
| **⚡ 快速录入** | 填 6 个核心数字，一键生成完整日报 |
| **📝 详细编辑** | 手动微调每条发现、建议、竞品信息 |
| **🏪 多门店管理** | 新增/删除门店，切换门店编辑 |
| **📋 建议追踪** | 记录每条建议的执行情况和效果，自动统计执行率 |
| **🔗 复制老板链接** | 一键生成当前门店的只读链接，发给老板 |
| **💾 本地存储** | 数据保存到浏览器 localStorage，刷新不丢失 |

### 用户端 (`view.html`)

| 功能 | 说明 |
|------|------|
| **📊 经营看板** | 评分 + 6 项核心指标，一目了然 |
| **🔍 AI 经营发现** | 4 条数据驱动的分析与建议 |
| **🎯 今日行动建议** | 3 条具体可执行的运营动作 |
| **🏪 竞争动态** | 周边竞品跟踪与应对策略 |
| **📋 建议追踪** | 过去 7 天的建议执行记录与效果统计 |
| **📱 移动端优化** | 手机自适应，老板随时随地查看 |

## 快速开始

### 本地使用

1. 下载 `store-dashboard/` 文件夹
2. 双击 `index.html` 在浏览器打开
3. 点击右上角 **「⚙️ 管理数据」** → **「⚡ 快速录入」**
4. 填几个数字 → **「🤖 一键生成日报」**
5. 截图发给老板，或点 **「🔗 复制老板链接」** 发链接

### 线上部署

推送到 GitHub Pages：

```
https://你的用户名.github.io/store-dashboard/     ← 管理员端
https://你的用户名.github.io/store-dashboard/view.html?store=coffee  ← 用户端
```

详见 [部署说明](#部署)。

## 用户端详解

用户端是老板看到的只读页面，**没有任何编辑入口**。

### 访问方式

```
https://.../view.html?store=coffee    ← 看咖啡店
https://.../view.html?store=bbq       ← 看烧烤店
https://.../view.html?store=tea       ← 看奶茶店
```

如果不传 `?store=` 参数，默认显示第一家门店。

### 与管理端的区别

| 对比项 | 管理员端 | 用户端 |
|--------|---------|--------|
| 编辑功能 | ✅ 完整增删改查 | ❌ 无 |
| 门店切换 | ✅ 所有门店 | ✅ 仅可见门店 |
| 管理按钮 | ✅ ⚙️ 编辑数据 + 🔗 复制链接 | ❌ 无 |
| 建议追踪 | ✅ 可标记执行/填效果 | ✅ 只读展示 |
| 页面布局 | 全功能 | 精简移动端优化 |

## 智能生成引擎

核心函数 `smartGenerate()` 位于 `index.html` 的 JavaScript 中。它是一套**基于规则的模板引擎**，不需要外部 AI API。

### 生成逻辑

```
输入（6 个核心数字）
  ├── 昨日营收 → 计算评分、同比/环比、标签
  ├── 进店客流 → 计算客流变化率、外卖预估
  ├── 客单价   → 计算客单变化率
  ├── 点评评分 → 计算评分变化、评分标签
  ├── 差评情况 → 生成对应发现和建议
  ├── 社交数据 → 生成内容建议
  ├── 亮点     → 生成主推建议
  ├── 天气     → 生成环境相关建议
  └── 竞品     → 生成竞品分析和应对策略
        ↓
输出
  ├── score (0-100)
  ├── tags (3 个)
  ├── findings (4 条 AI 发现)
  ├── advice (3 条行动建议)
  ├── competitors (2-3 个竞品)
  └── 自动记录到 adviceHistory
```

### 评分计算规则

```
评分基数：
  评分 > 4.5 → 92 分
  评分 > 4.0 → 85 分
  评分 > 3.5 → 72 分
  评分 > 3.0 → 60 分
  否则 → 50 分

调整：
  营收 > 10000 → +5 分
  营收 < 3000  → -10 分
  客流 > 200   → +3 分
  客流 < 50    → -5 分

最终：限值在 10-100 之间
```

### 建议生成规则

每条建议根据输入数据中的关键词触发不同模板：

```
差评 → 生成「回复差评」建议
社交含"制作" → 生成「拍摄制作过程」建议
天气含"雨" → 生成「外卖推广」建议
竞品 → 生成「差异化定位」建议
亮点 → 生成「重点推广」建议
```

## 建议追踪系统

### 数据模型

```javascript
adviceHistory: [
  {
    date: "07/23",  // 日期 (MM/DD)
    advice: [
      {
        title: "📱 拍一条老板出镜视频",  // 建议标题
        executed: "done",   // 状态: pending | done | skip
        result: "播放 1.2w"  // 实际效果
      }
    ]
  }
]
```

### 执行流程

```
① 点击「一键生成日报」
  → 自动将当天生成的 3 条建议记录到 adviceHistory
  → 状态默认 "pending"（待执行）

② 管理员在「详细编辑 → 建议追踪」中标记
  → ✅ 已执行（done）：填写实际效果
  → ⏭ 跳过（skip）：标记不执行的原因
  → ⏳ 待执行（pending）：保持等待

③ 看板自动统计
  → 过去 7 天的建议总数
  → 执行率 = 已执行 / 总建议
  → 有效建议 = 效果中包含正向关键词的数量
```

### 给老板的价值

老板看到的不只是"今天该做什么"，还有**之前建议的执行效果**：

```
你昨天建议我拍视频 → 我拍了 → 播放 1.2w → 有效！
你前天建议我回复差评 → 我回了 → 评分回升 → 有效！

→ 老板觉得这 999 元/月花得值
```

## 数据说明

### 数据存储

当前版本使用 **浏览器 localStorage** 存储数据：

```
localStorage 键名: 'storeDashboardData'
数据格式: JSON 序列化的门店对象
```

### 数据示例结构

```json
{
  "coffee": {
    "name": "XX咖啡店",
    "branch": "湖滨店",
    "score": 85,
    "revenue": 9623,
    "revenueYoY": "+8%",
    "revenueMoM": "+3.2%",
    "traffic": 168,
    "trafficChg": "+12%",
    "ticket": 57.3,
    "ticketChg": "+5%",
    "social": "2.3w",
    "socialChg": "+32%",
    "rating": 4.2,
    "ratingChg": "-0.3",
    "delivery": 47,
    "deliveryChg": "+8%",
    "repeat": "23%",
    "repeatChg": "+1.8%",
    "tags": [
      { "text": "📈 小红书收藏 +32%", "cls": "" }
    ],
    "findings": [
      { "source": "小红书", "data": "收藏率上涨 32%", "suggest": "继续拍摄制作过程" }
    ],
    "advice": [
      { "title": "📱 拍一条视频", "desc": "用手机拍摄 45 秒", "pred": "预计浏览 2万" }
    ],
    "competitors": [
      { "name": "瑞幸", "action": "推29元套餐", "tag": "不要跟价", "tagCls": "warn" }
    ],
    "adviceHistory": [
      { "date": "07/23", "advice": [{ "title": "...", "executed": "done", "result": "播放1.2w" }] }
    ]
  }
}
```

### 注意事项

- **数据隔离**：localStorage 按浏览器隔离，不同设备的老板看不到对方的数据
- **数据持久**：关闭页面不会丢失，但清除浏览器缓存会丢失
- **建议导出**：后续可加数据导出功能（JSON/CSV）

## 部署

### 方案一：Vercel（推荐，免费）

1. 注册 [vercel.com](https://vercel.com)
2. 将 `store-dashboard/` 文件夹拖入浏览器
3. 自动获得 `https://项目名.vercel.app` 链接

### 方案二：GitHub Pages（当前使用）

1. 注册 [github.com](https://github.com)
2. 创建仓库，上传 `store-dashboard/` 内容
3. 仓库 Settings → Pages → 选择 main 分支
4. 获得 `https://用户名.github.io/仓库名/` 链接

### 方案三：自定义域名

在 GitHub Pages 或 Vercel 绑定自己的域名（需购买，约 50-100 元/年）
