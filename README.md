# AI 门店增长顾问 — 经营看板

一个面向实体门店老板的 **AI 经营日报系统**。管理员录入数据，系统自动生成经营分析、行动建议，通过 GitHub 云端自动同步，老板在手机上看只读看板。

> **产品模式：** 管理员一台电脑录入 → 数据自动同步到云端 → 老板手机随时查看最新经营日报，无需安装任何 App。

> **核心理念：** 先用手工+工具验证需求，再逐步自动化。  
> 参考：[Wizard of Oz MVP](https://zh.wikipedia.org/wiki/%E7%B6%A0%E9%87%8E%E4%BB%99%E7%B8%AB%E5%9E%8B%E6%9C%80%E5%B0%8F%E5%8F%AF%E8%A1%8C%E7%94%A2%E5%93%81)

## 快速开始

### 本地使用

1. 下载 `store-dashboard/` 文件夹
2. 双击 `index.html` 在浏览器打开
3. 点击门店栏右侧的 **「⚙️ 编辑数据」** → **「⚡ 快速录入」**
4. 填 4 个数字（昨日营收/进店客流/客单价/点评评分）→ **「🤖 一键生成日报」**
5. 截图发给老板，或点 **「🔗 复制老板链接」** 发链接

> 💡 本地双击打开时数据只存在本机浏览器；要让老板在手机上看到，请按下面的**多设备云同步**配置。

### 线上部署

推送到 GitHub Pages：

```
https://你的用户名.github.io/store-dashboard/     ← 管理员端
https://你的用户名.github.io/store-dashboard/view.html?store=coffee  ← 用户端
```

详见 [部署说明](#部署)。部署后建议开启 [多设备云同步](#多设备云同步)，让老板端自动拉取最新数据。

## 用户端详解

用户端是老板看到的只读页面，**没有任何编辑入口**。打开页面时会自动从 GitHub 云端拉取最新数据（无需 Token，走公开仓库的 raw URL），所以老板看到的永远是最新状态。

### 访问方式

```
https://.../view.html?store=coffee    ← 看咖啡店
https://.../view.html?store=bbq       ← 看烧烤店
https://.../view.html?store=tea       ← 看奶茶店
```

链接由管理员端的 **「🔗 复制老板链接」** 一键生成。**不传 `?store=` 或参数无效时，页面会提示「请通过老板发送的链接访问」**，不会展示门店。

### 与管理端的区别

| 对比项 | 管理员端 | 用户端 |
|--------|---------|--------|
| 编辑功能 | ✅ 完整增删改查 | ❌ 无 |
| 门店切换 | ✅ 所有门店 | ✅ 所有门店（同一份数据） |
| 管理按钮 | ✅ ⚙️ 编辑数据 + 🔗 复制链接 | ❌ 无 |
| 建议追踪 | ✅ 可标记执行/填效果 | ✅ 只读展示 |
| 数据来源 | localStorage + 手动/自动同步云端 | 打开时自动从云端拉取 |
| 页面布局 | 全功能 | 精简移动端优化 |

## 多设备云同步

系统通过 **GitHub Contents API** 把全量数据存到仓库的 `data/store-data.json`，实现多设备共享。这是目前的产品模式核心：**管理员一台电脑录入，老板手机随时看最新**。

### 工作原理

```
管理员端 (index.html)
  ├── 设置 Token → 保存到 localStorage (github_token)
  ├── ⬇️ 从云端拉取   → GET /contents/data/store-data.json → 覆盖本地
  ├── ⬆️ 推送到云端   → PUT /contents/...（带 sha 防冲突）
  └── 自动推送        → 快速生成/保存编辑/新增/删除门店时静默同步

用户端 (view.html)
  └── 每次打开页面    → 从 raw.githubusercontent.com 拉取最新数据（无需 Token）
```

### 使用步骤

1. 在 GitHub 生成 Personal Access Token（勾选该仓库，`Contents: Read and write` 权限）
2. 管理员端 → **⚙️ 编辑数据** → 云同步区填入 Token → **💾 保存 Token**
3. 点 **⬆️ 推送到云端** 完成首次上传
4. 之后每次操作自动同步；老板打开 `view.html` 链接即为最新数据

### 注意事项

- Token 只存在你的浏览器 localStorage，不会上传到云端
- Token 泄露后请在 GitHub 撤销重新生成（页面填写的 Token 需与权限匹配）
- 云端文件是 UTF-8 编码；仓库早期版本曾因 `atob` 解码不当产生中文乱码，现已修复（拉取/推送均按 UTF-8 处理）

## 智能生成引擎

核心函数 `smartGenerate()` 位于 `index.html` 的 JavaScript 中。它是一套**基于规则的模板引擎**，不需要外部 AI API。

### 生成逻辑

```
输入（4 个核心数字 + 该门店历史数据 dailyMetrics）
  ├── 昨日营收 → 对比近 7 日均值，计算同比/环比、营收趋势
  ├── 进店客流 → 对比近 7 日均值，计算客流变化率
  ├── 客单价   → 客单水平与提升建议
  └── 点评评分 → 计算评分变化、评分标签
        ↓
输出
  ├── score (0-100)
  ├── tags (3 个)
  ├── findings (4 条：营收/客流/评分/综合诊断)
  ├── advice (3 条行动建议，按营收客流分档)
  ├── competitors (2 条占位，可手动编辑)
  ├── delivery / repeat 自动推算
  ├── 今日数据写入 dailyMetrics（趋势对比依据）
  └── 3 条建议自动记录到 adviceHistory（状态 pending）
```

没有历史数据的门店会走阈值兜底逻辑，同样能生成完整日报。

### 评分计算规则

```
评分基数：
  评分 > 4.5 → 92 分
  评分 > 4.0 → 85 分
  评分 > 3.5 → 72 分
  评分 > 3.0 → 60 分
  否则 → 50 分

调整：
  营收 > 10000 → +5 分
  营收 < 3000  → -10 分
  客流 > 200   → +3 分
  客流 < 50    → -5 分

最终：限值在 10-100 之间
```

### 建议生成规则

每日生成 4 条经营发现 + 3 条行动建议，规则如下：

```
发现（findings）4 条：
  📊 营收：与近 7 日均值对比，高于/低于均值及幅度
  👥 客流：与近 7 日均值对比 + 客单价水平
  ⭐ 评分：环比变化，处于正常/偏低水平
  💡 诊断：综合营收/客流趋势给出一句话诊断

行动建议（advice）3 条：
  第 1 条（营收+客流组合分档）：
    营收客流双下滑 → 分析原因、稳住基本盘
    客流 > 150     → 推新品/套餐提升客单
    客流 < 80      → 拍视频引流到店
    其他           → 套餐组合提升客单
  第 2 条（评分档）：
    评分 < 3.8 → 紧急回复差评
    评分 ≥ 4.5 → 维护好评、鼓励晒单
    其他       → 常规满意度维护
  第 3 条（趋势组合）：
    营收升/客流升 → 会员充值活动
    营收升/客流降 → 限时优惠促进到店
    其他           → 优化菜单结构
```

> 说明：早期版本曾按「差评/天气/亮点」等关键词触发模板，现改为**历史趋势 + 阈值分档**驱动，更贴合每日录入的经营数据。

## 建议追踪系统

### 数据模型

```javascript
adviceHistory: [
  {
    date: "07/23",  // 日期 (MM/DD)
    advice: [
      {
        title: "📱 拍一条老板出镜视频",  // 建议标题
        executed: "done",   // 状态: pending | done | skip
        result: "播放 1.2w"  // 实际效果
      }
    ]
  }
]
```

### 执行流程

```
① 点击「一键生成日报」
  → 自动将当天生成的 3 条建议记录到 adviceHistory
  → 状态默认 "pending"（待执行）

② 管理员在「详细编辑 → 建议追踪」中标记
  → ✅ 已执行（done）：填写实际效果
  → ⏭ 跳过（skip）：标记不执行的原因
  → ⏳ 待执行（pending）：保持等待

③ 看板自动统计
  → 过去 7 天的建议总数
  → 执行率 = 已执行 / 总建议
  → 有效建议 = 效果中包含正向关键词的数量
```

### 给老板的价值

老板看到的不只是"今天该做什么"，还有**之前建议的执行效果**：

```
你昨天建议我拍视频 → 我拍了 → 播放 1.2w → 有效！
你前天建议我回复差评 → 我回了 → 评分回升 → 有效！

→ 老板觉得这 999 元/月花得值
```

### 注意事项

- **多设备同步**：配置云同步后，数据通过 GitHub 云端共享；管理员端保存时自动推送，用户端打开时自动拉取

- **数据导出**：后续可加数据导出功能（JSON/CSV）

## 部署

### 方案一：Vercel（推荐，免费）

1. 注册 [vercel.com](https://vercel.com)
2. 将 `store-dashboard/` 文件夹拖入浏览器
3. 自动获得 `https://项目名.vercel.app` 链接

### 方案二：GitHub Pages（当前使用）

1. 注册 [github.com](https://github.com)
2. 创建仓库，上传 `store-dashboard/` 内容
3. 仓库 Settings → Pages → 选择 main 分支
4. 获得 `https://用户名.github.io/仓库名/` 链接
5. 部署完成后按 [多设备云同步](#多设备云同步) 配置 Token 并**首次推送到云端**（仓库需含 `data/store-data.json`）

### 方案三：自定义域名

在 GitHub Pages 或 Vercel 绑定自己的域名（需购买，约 50-100 元/年）
